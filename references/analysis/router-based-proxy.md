# Роутерное проксирование и сценарии OpenWrt/podkop

Данный документ содержит аналитические выводы
и не является прямым пересказом источника.

## Назначение

Этот файл нужен для анализа ситуаций, где логика обхода вынесена с конечного устройства на роутер или близкую к нему сетевую точку.

## Аналитическая рамка

Методичка прямо фиксирует только одно базовое ограничение: она не рассматривает случай, когда VPN разворачивается на пользовательском маршрутизаторе, и в таком сценарии на клиентском устройстве могут отсутствовать локальные артефакты.

Из этого в рамках данного репозитория можно аналитически выводить следующее:

- часть клиентских признаков на устройстве становится менее наблюдаемой;
- значение серверных факторов не исчезает;
- роутерный сценарий требует отдельного разбора, а не механического переноса выводов из сценария «VPN на устройстве».

## OpenWrt и podkop

Упоминания OpenWrt и podkop в этом файле являются аналитической привязкой к типу архитектуры, а не цитатой из методички.

Использовать их следует как ярлык для класса сценариев:

- проксирование и маршрутизация вынесены на роутер;
- устройство может не иметь локальных VPN-флагов;
- детект по клиентским API может ослабляться;
- серверные признаки по GeoIP, ASN, hosting и репутации IP сохраняют значение.

## Как анализировать такие схемы

1. Сначала отделять клиентские признаки на устройстве от серверных признаков.
2. Затем проверять, какие локальные артефакты действительно могут отсутствовать.
3. После этого оценивать, остается ли серверный риск по GeoIP, ASN, hosting, репутации IP и истории сессий.
4. Отдельно помечать, что вывод о полной «невидимости» схемы не подтверждается одной только методичкой.

## Осторожный вывод

Корректный аналитический вывод для этого файла:

- роутерное проксирование может ослаблять клиентский детект на устройстве;
- этого недостаточно, чтобы автоматически считать схему безопасной от всех способов выявления;
- итоговая оценка должна строиться на сочетании официальных признаков и явном обозначении пробелов методики.
